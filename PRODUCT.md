# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Confirmed: React + Vite + Tailwind frontend, Node/Express backend, SQLite, JWT auth (CodeBox bootcamp recommended stack, minus hosted DB).

## Users

Developers and bootcamp peers. Primary evaluator: developers at CodeBox Demo Day deciding who they want to build with, watching a 90-second pitch. Real usage: a developer or small team watching whether their APIs are up.

## Product Purpose

Signal is a live API uptime monitor. Users register HTTP endpoints; the backend probes them on a schedule, stores every check, and streams results to the dashboard in real time. Success on demo day: the audience sees architectural skill (scheduler, SSE streaming, layered backend, auth, CRUD) in under 90 seconds.

## Positioning

Not a todo list: the server does work on its own (scheduled probes, live push), the UI reacts without polling.

## Capabilities and Constraints

- Monitors: full CRUD (name, URL, method, interval, expected status, pause/resume).
- Checks: stored per probe (status, latency, error), history + uptime %.
- Live: Server-Sent Events push each check to the browser.
- Auth: signup/login, bcrypt, JWT; each user sees only their own monitors.
- Built-in public `/api/demo/flaky` endpoint so the demo works offline.
- Inferred (not user-confirmed): no alerting/email, no multi-user teams.

## Brand Commitments

Name: Signal. User chose the visual lane "Ethereal dark glass" (OLED black, mesh orbs, double-bezel glass cards, hairlines, spring motion).

## Evidence on Hand

None: no customers, uptime claims, or benchmarks exist. All demo data is generated by the app itself.

## Product Principles

1. The system visibly does work: show live pushes, not static tables.
2. Architecture is the pitch: every layer should be explainable in one sentence.
3. Never blank-screen: loading, error, and empty states are designed.
